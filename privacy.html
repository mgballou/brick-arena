Privacy

Brick Arena records how matches play so its maker can understand player behavior and Jev's choices, never who you are.

What is recorded

  • Player events, sent to PostHog when analytics is enabled: session and title-screen activity, rules opened, matches and levels started and ended, balls lost, pauses and resumes, and brief records of Jev's choices. Event-specific details can include screen size and input type, level, score, and timing. These events help measure where players lose balls and how Jev performs.
  • The match record, sent to the game server and stored as rows in Supabase: each question sent to Jev with its board, every launch and lost ball, each side's progress about once a second, and each level's result. This supports replaying and analyzing matches.
  • One anonymous id: PostHog creates a random id on your first visit and keeps it in this browser's local storage, so returning visits can be counted together. Brick Arena never identifies it or puts it in a match record. Clearing this site's data or opting out ends it.

What is never recorded

  • Your IP address in Brick Arena's records. PostHog IP capture is off. The game server reads the request address in memory to enforce its daily Jev call limit, but does not write it to match records.
  • Names, emails or accounts. The game has none and takes no typed text.
  • A fingerprint or a profile of you. PostHog keeps no person profiles.
  • A recording of your screen. Session replay is off.
  • Debug play, or a match the stand-in plays in Jev's place.

What Jev receives

The game server sends TypeSafe's Jev the current game board, the game's rules, and one question with a closed list of choices: where to catch the ball, which falling power-up to chase, or which ball to play. The request contains game state, not your name, account, or PostHog id. The browser sends the request to Brick Arena's server; the server forwards it to TypeSafe.

Who keeps it, and where

  • PostHog stores the player events. Region: [US or EU Cloud].
  • Supabase stores match rows in West US (Oregon). The game server also keeps one match file on its hosting disk.
  • Only the game's maker reads either, through PostHog's and Supabase's own sign-ins.

How long

  • PostHog events: one year on PostHog's free plan.
  • In Supabase, detailed Jev calls, match events, and level-progress rows are deleted by a weekly job after the match has been started for more than 90 days. The match summary row, including its dates, result, and Jev tally, remains; the job does not give it an expiry.
  • The server-side match file follows the hosting disk's lifetime. The game's maker can run a monthly export to create a local backup; it is manual, and the maker controls how long that file is kept.

How to opt out

  • Choose Opt out beside the notice on the title screen. This browser then sends no events and no match record, and the anonymous id ends. The game plays exactly the same. The browser remembers the choice, and the same spot offers Opt back in.
  • Turn on Do Not Track in your browser. The game treats it as the same opt-out.
  • Clearing this site's data forgets the choice along with the id, so opt out again afterwards.
